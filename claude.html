01 · What moved

Three steps,
two moved

Every wish goes through three steps. Drawing and coding start together while the wish is still being screened. Claude took over the two text steps. It can't make images, so the drawing stays on Codex.

Codex Luna→Haiku 5.5

A 12-frame pixel-art sprite sheet. Claude can't generate images.

Codex image toolunchanged

Codex worked as an agent: open a shell, write the file, run the checker, read the error, try again. Claude does it in one request. The rules and two sample creatures sit in a cached system prompt, the wish goes in, and the whole file comes back. My server runs the same checker, and a failure gets one repair turn.

06 · The switch

One file,
no restart

The model lives in a file, not in the code. The server checks the file's timestamp on every wish, so a change applies to the next one. Pets already in flight finish on the model they started with. A broken file is ignored. Try it.

08 · What I got wrong

My bug,
not the API

Calls ran one at a time25 s → 4.4 sMy first full run looked slow and I blamed API load. The SDK's default fetch was queueing my concurrent calls. A plain HTTP/1.1 agent fixed it.
Old results got re-scored2 wrong numbersThe harness scored every file left in a results folder, so a 3-wish test was graded on 43. It now scores only what you asked for.
"Paper-cutout style"14 / 29 failingHaiku kept adding a style to the illustrator's prompt. One sentence in the shared prompt fixed it, for Codex too.
Build fed declined wishes29, not 43Haiku returned no code for wishes the screen should stop first. The build numbers only count the 29 that should get through.
09 · What I'd reuse

Four rules

01Pick the smallest model that passes your checks.
02Write the checks before you pick the model.
03Put the model choice in a file, not in code.
04Time your own plumbing before you blame the API.
